Engineering Methodology

How We Work

A disciplined 5-stage lifecycle bridging user needs, regulatory standards, and rigorous software verification.

  1. 1

    Discover

    We conduct stakeholder interviews and PACT analysis (People, Activities, Context, Technology) to uncover the exact operational risks, shift routines, and compliance gaps on the ground.

  2. 2

    Design

    We formulate formal user stories with testable acceptance criteria, database entity-relationship diagrams (ERDs), API specifications, and interactive UX wireframes.

  3. 3

    Build

    Our engineers implement a clean three-tier architecture. Role-based access control (RBAC), validation, and session integrity are strictly enforced on the server rather than trusting client state.

  4. 4

    Verify

    A requirements-based test plan keeps every client requirement traceable to an automated test. We run unit tests (pytest, Vitest), end-to-end browser tests (Playwright), and WCAG audits.

  5. 5

    Refine

    We run structured feedback sessions with client trainers, shift supervisors, and operatives, fine-tuning visual clarity, prompt language, and scenario realism before final sign-off.

PACT Analysis in Practice

Before writing code for SafeShift, we mapped out the operational environment:

  • People: High-turnover warehouse operatives with diverse language backgrounds and varied digital literacy.
  • Activities: Repetitive heavy lifting, pallet de-stacking, and sharing narrow lanes with moving forklifts.
  • Context: Fast-paced, noisy distribution hubs with strict 24-hour dispatch targets.
  • Technology: Shared terminal PCs and ruggedised mobile touch tablets requiring quick session handoffs.

Requirements Traceability Matrix

Every feature in SafeShift is directly indexed to a verifiable test and HSE regulation:

  • REQ-01 (Hazard Recognition): Traced to Test Suite `test_hazard_spotting.py` & HSE HSG76.
  • REQ-02 (RBAC Security): Traced to Test Suite `test_auth_permissions.py` (JWT tokens).
  • REQ-03 (Audit Persistence): Traced to Database migration `003_attempts_audit_table.sql`.
  • REQ-04 (Accessibility): Traced to automated Axe-core automated accessibility suite.
